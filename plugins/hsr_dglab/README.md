# HSR PunishHime（惩罚姬）插件 - 崩铁·挨打就电（veritas + OCR 双路线）

崩坏：星穹铁道精确惩罚插件。**双数据源、多模块架构**：

| 模块 | 数据源 | 状态 |
|---|---|---|
| 常规战斗（角色血量/盾量/倒地） | veritas 内存钩子 | OK 完整 |
| 常规战斗（OCR 路线） | 截图识别 | 预留（占位未实现） |
| 货币战争（总血量） | OCR 扣血飘字 / 总血量数值 / veritas uid | OK 完整 |

公式移植自"挨打就电"插件（受伤加成分段曲线、连续叠加、盾量惩罚），两条路线
统一进入同一套惩罚管线（阈值 -> 加成 -> 叠加 -> 强度/波形 -> 持续电击）。

## 安装

1. 整个 hsr_dglab 文件夹放入惩罚姬的 plugins 目录
2. （常规战斗模块）安装并运行 veritas（github.com/hessiser/veritas）
   - 默认监听 127.0.0.1:1305，与本插件默认配置一致
3. （货币战争模块）安装 Umi-OCR（github.com/hiroi-sora/Umi-OCR）
   - 全局设置 -> 开启 HTTP 服务，端口与插件配置一致（挨打就电同款 1395）
   - 模型建议选英文/数字模型（Umi-OCR 桌面设置 -> OCR 选项 -> 语言/模型 = models/config_en.txt）；
     插件发请求时也会带上该模型参数（cw_ocr_model 可留空跟随全局）
4. 启动惩罚姬 -> 启动本插件 -> 打开配置面板

## 货币战争模块（总血量）

三种数据输入（面板"总血量数据输入"选择）：

### A. OCR 扣血飘字（默认，推荐）

货币战争里被打时屏幕上会弹出红色扣血飘字（如 -10）。插件轮询识别该区域：

- 框选工具：面板「框选区域」按钮 -> 全屏覆盖层拖拽框住数字 -> 松开自动填入坐标（物理像素）
- **滤镜目标色**（默认 #F78679）与**滤镜近似度**（默认 30）就在掉血设置旁边，可随时调：
  - 挨打就电同款滤镜：颜色距离 <= 容差x3 的像素保留为黑，其余变白，只留数字
  - 识别不稳就微调近似度（过大混入背景，过小丢笔画）；多个颜色用 | 分隔
- 识别到 -N -> 立刻按本次扣血量 N 触发电击（走受伤加成公式）
 - "+"开头的获得量自动忽略；同一数字在去重窗口内（cw_delta_dedup，默认 1.5 秒）不重复触发
 - 消散碎片抑制：飘字消失动画残影被读成已触发数值的子串（如 -10 残影读成 1）时自动忽略
 - 采样频率 cw_ocr_interval 默认 0.2 秒（5 次/秒，下限 0.1）；滤镜 numpy 向量化（大区域毫秒级），
   墨迹 <12px 跳过请求、按墨迹包围盒裁剪后再发 OCR；实测 Umi 单请求 30-96ms，5Hz 无压力
 - 框选建议：区域完整覆盖飘字「出现 -> 上浮 -> 消失」路径，数字完整在框内时识别最稳
 - 电击后可接**持续电击**：持续时长内周期重发波形，结束后清波形归零（均可配）

### B. OCR 总血量数值（差值模式）

cw_ocr_mode = pool：框选当前血量数字区域（推荐：屏幕下方血量数值，区域尽量小），与上次读数做差值作为掉血量。
首次读数作为基准不触发。血量满值 100、可为负数（保留符号解析）；单刀最大 ~200（100 -> -100），
读数跳变超过 300 或 |读数| > 999 视为误读丢弃。推荐滤镜双色：#FFFFFF（平时）|#FFBE68（掉血时），
用 | 分隔。5Hz 采样下一次掉血一次电击，间隔 <0.2s 的连续掉血会合并为一次差值。

**读数稳定性（实测视频校准）**：血量数字变化时有弹跳/闪烁动画，会产生单帧垃圾读数
（'1Q'、'19'、丢末位的 '6'）。引擎三重防御：数字间空格拼接（'7 9'->79）、
0.6 秒内同值出现 2 次才采纳、新值是当前血量前缀（丢位）时丢弃。框选区域务必比
数字大一圈——弹跳幅度可观（实测数字位移可达 ±50px），框太小会裁掉数字。

**加号检测**（cw_plus_*，挨打就电 plus 检测一模一样）：多个检测点 + 多个颜色一一对应，
每轮识别前单像素采样，每点对整组颜色做曼哈顿近似（tol*3），**全部命中才继续识别**；
再来一组反向检测点/反向颜色——任一反向点命中即判定不在结算画面，跳过识别（防在菜单/
其它界面误触）。检测点与识别区域共用一次截图。坐标为窗口客户区相对（跟随窗口移动），
格式 "x,y|x,y"。用「添加检测点(取色)」逐点取色（点+色一步到位），「添加反向点(取色)」
同理。启用后「测试识别」附带加号结果位串（正位!反位，每位一个点，1=命中）。
稳定窗口随采样间隔自适应：max(1.2s, 采样间隔×3)，同一读数窗口内出现 2 次才采纳。

旧的飘字方案（delta：连续确认 + 碎片抑制 + 静态拒识）代码保留但已停用——飘字叠加会误读
（-5 与 -10 叠读成 210），常驻 UI 文字（1-3 X）会幻影触发；血量差值方案天然规避这些问题。

## 常规战斗模块（veritas）

veritas 的 OnStatChange 精确到每个角色，天然规避 OCR 三大痛点
（多角色难分 / 大招演出隐藏 HUD / 阵容变动）：

- 掉血 -> 阈值过滤 -> 受伤加成 -> 叠加 -> 电击
- 盾量惩罚（默认关）、有盾时阻止血量惩罚、倒地重罚、战斗结束清零，均可配
- 战斗模块数据输入可选 veritas / ocr（占位）/ both

## 惩罚公式（移植自挨打就电）

> 默认参数全部取自挨打就电原版（基础强度 A20/B19、盾量 A18/B17 且默认开启、
> 掉血阈值 1、受伤参考值 70、最大加成 10、叠加 +1/上限 200/窗口 1.5x、
> 自然回落 instant、扫描间隔 0.1s、health/shield 波形原样），
> A/B 通道强度不同时分通道设置（挨打就电同款双通道手感）。
> 崩铁单次伤害数值远大于卡拉彼丘，若每次都顶格加成，把"中等伤害参考值"
> 调大到典型单次掉血量即可恢复分段曲线手感。

### 受伤程度加成

```
r = 本次掉血 / 中等伤害参考值(默认3000)
轻伤  r < 10%    -> 加成 = 最大加成 x 0.2
中伤  10% ~ 50%  -> 线性过渡 0.2 -> 0.6
重伤  50% ~ 100% -> 二次曲线加速 0.6 -> 1.2
极限  r >= 100%  -> 加成 = 最大加成 x 1.2
```

### 连续挨打叠加（overlap）

叠加窗口内再次挨打会持续累加强度（按强度上限做接近度抑制），窗口外只有
单次加成生效。支持 5 种自然回落方式（instant/linear/percent/ratio_accel/script）。

### ratio 强度公式（默认，veritas 角色 HP/盾）

按掉血占角色血量上限的比例驱动，替代绝对掉血参考值，适配崩铁大额伤害：

```
raw = 伤害系数 x 掉血占比%          （占比 = 掉血 / 角色血量上限）
低于强度阈值的掉血不惩罚
加成 = 阈值 + 压缩(超出部分)         （压缩器 sqrt/log/linear）
超过向上压缩器的部分按 25% 保留      （软上限）
残血角色自身残血 -> x(1+残血强度系数)
全队残血人数 -> x(1+人数x残血人数系数)
多角色窗口内受伤角色数 n>=2 -> x(1+(n-1)x多角色系数)，且波形按角色轮转相位
近5秒第 f 次触发 -> x max(0.2, 1-(f-1)x频率压缩器)   （频率越高强度越低）
战斗轮次 -> x(1+轮次x轮次系数)
```

残血持续电：任一角色血量低于残血阈值时持续发普通波形，强度 = 持续电基础
+ 每多一个残血角色的加成；全部脱离残血后自动清波结束。

## 配置面板

五个页签：实时状态 / 常规战斗 / 货币战争 / OCR 识别 / 波形配置

> 页面与引擎通过文件桥通信（%TEMP%/hsr_dglab_ipc/）：当前 server 版未开放
> 插件级 HTTP 接口（POST /plugin/{name}/{action} 一律 405），实时状态走
> status.json 心跳、动作走 cmd.json、配置直接读写插件 config.json——
> 插件未启动时也能编辑保存，启动后自动生效。

- 实时状态：角色血条/盾条、挨打统计、强度调节、测试电击/连接、
  **HUD 悬浮窗开关**、**手柄控制开关**、**暂停/恢复按钮**
- 货币战争页：实时总血量卡片 + 惩罚/持续电击设置 + **总血量惩罚折叠区**
  （颜色滤镜 + 近似度 + 取色按钮、识别区域 + 框选按钮、跟随游戏窗口、
  测试识别、**诊断截图**）
- OCR 识别页：Umi-OCR 连接设置（启用/地址/模型/间隔）
- 输入框自动填充 config.json 默认值（挨打就电原版数值），未保存过也有初始值
- 截图后端移植自挨打就电（GDI + 游戏窗口客户区跟随，支持窗口移动）
- 窗口置顶（右上角勾选）；所有参数保存后即时生效

## 游戏内悬浮窗（HUD）

移植挨打就电 overlay 的成熟模型：常驻线程 + 永不销毁 root（stop 只隐藏，
插件重启复用实例——tk 线程亲和崩溃的根源就是反复销毁重建）。游戏左上角
半透明显示：首角色血量 | 强度 A/B | 叠加 | CW 总血/累计掉血/打击数 |
持续电击中 | 最近挨打。hud_enabled 实时生效（面板开关即可，无需重启）。

## 暂停/恢复

- 面板按钮：实时状态页「暂停/恢复惩罚输出」
- 手柄（gamepad_enabled，默认关）：**LB+RB 同按**切换（XInput，无需第三方库）
- 暂停时立即清波形清强度，HUD 显示 ⏸，恢复后管线原样继续

## 诊断截图

货币战争页「诊断截图」按钮：把当前 OCR 识别区域 + 游戏窗口客户区
（跟随窗口时自动换算偏移）存为 PNG 到插件目录 screenshots/，文件名带
时间戳。识别不对时截给我即可远程排查（无需第三方图片库，内置 zlib PNG 编码）。

## 命令桥（页面 <-> 引擎）

%TEMP%/hsr_dglab_ipc/：cmd.json（页面写入）-> 引擎**独立线程派发**
（框选/取色等阻塞动作绝不卡桥）-> cmd_result.json 回写（原子替换 +
共享冲突重试）。过期命令（>20s，页面已超时放弃）直接丢弃防幽灵弹窗；
框选/取色引擎侧互斥，重复点击即时得到提示。
